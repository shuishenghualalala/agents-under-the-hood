# 第 12 章：最小复刻指南

> 本章导读：如果要从零重建一个"最小可用"的 dsh，需要哪些组件、按什么顺序、哪些可以砍。本章是前面所有章节的逆向工程——把架构还原成一份购物清单。读完你应该能判断：哪些是这个架构的骨架（砍掉就不是 dsh 了），哪些是肌肉（可以先不要）。

## 12.1 骨架：六个不可砍的组件

按实现顺序：

### ① 插件运行时（最小 Cordis）

```text
Context（proxy 服务容器 + inject 检查）
  + Fiber（PENDING→ACTIVE 状态机 + epoch 依赖重载）
  + effect/dispose（一切注册可逆）
  + 事件：emit / serial / waterfall 三种就够（parallel/bail 可后补）
```

这是地基。没有"注册即可逆"，后面所有可替换性都不存在。约几百行可实现最小版。

### ② 仅追加会话日志 + surface 投影

```text
SessionEventMap（先只要 8 个事件：turn/start、turn/end、step/start、
  step/end、user/message、assistant/chunk、assistant/message、tool/result）
  + append（seq 连续、深冻结）
  + deriveMessages()（surface 投影）
  + session/event 广播
```

不要做 IO——持久化留给后面的 seam。先把"日志是唯一事实来源"立起来。

### ③ LLM 词汇与第一个适配器

```text
StreamChunk 封闭联合（block-start/text-delta/tool-call-delta/block-end/usage/finish）
  + LlmAdapter 抽象类（stream(options) 唯一必实现）
  + ctx.llm（registerAdapter + stream + llm/stream waterfall）
  + 一个手写 HTTP 的适配器（你的目标提供商）
```

词汇表是稳定契约——先定它，再写适配器。适配器契约里最重要的是：一次调用 = 一次尝试；usage 计数互不相交；错误规范化成 code。

### ④ 工具注册表与最小流水线

```text
ctx.tools（register 返回 disposer；schemas() 白名单投影）
  + 两段 waterfall：pre-execute（allow/deny/ask）+ execute
  + 两个内建工具就够演示：bash + file read/write
```

### ⑤ agent loop

```text
ReactLoopAgent：
  while (true) {
    claim inbox → pre-step waterfall → step/start
    → 落 user/message → deriveMessages() → llm/stream
    → 逐 chunk 落 assistant/chunk → assistant/message
    → 工具调度（先串行也行）→ tool/result
    → 有工具后续就下一步，没有就 turn/end
  }
  + inbox（先做内存版，持久化后补）
```

### ⑥ "模型可见 ⟺ 已记录"不变量

哪怕最小复刻也要这个：`llm/stream` 上 prepend 一个监听器，断言请求消息与 `deriveMessages()` 逐字节一致。**这是整个架构的免疫系统**——没有它，"日志是唯一事实来源"会悄无声息地被腐蚀。

## 12.2 第二批：让它能产品化

| 组件 | 为什么第二批 |
|---|---|
| 配置组装（bundle/patch 层 + cordis.yml loader） | 没有它也能跑（硬编码插件列表），但"一切可替换"只剩框架层 |
| 持久化后端（JSONL 就够） | 崩溃恢复与跨会话连续性的前提；注意 checkpoint 策略（请求前 flush） |
| 审批能力 | 工具能跑 shell 命令的那一刻起就需要；先做"全部 ask + 一个 CLI 应答者" |
| 沙箱（argv 包装） | 先只包 bash 一条路；fail-closed |
| 压缩（compaction） | replace surfaceOp 是唯一需要日志层配合的特性，投影器要预留 |
| 重试（agent/request-error 上的 Consumer） | 没有它 loop 脆；有了⑥的不变量，重试逻辑很好写对 |

## 12.3 可以最后做（或不做）的

preset/isolate realm（单能力集合时不需要）、continuable subagent（one-shot 就够）、workflow、Typert（手写几条 RPC 先顶着）、浏览器端插件树（先做服务端渲染或简单前端）、ACP、Python SDK、E2B。

## 12.4 复刻时最容易丢掉的四个设计

按"看着可有可无、丢了就变质"排序：

1. **waterfall 的 next() 语义**——如果扩展点退化成普通 pub/sub，"否决内建行为"就做不到，审批/压缩/回放全部失守。
2. **原始 chunk 入日志**——只存组装后的消息会丢掉回放保真与失败请求的 usage 记账。
3. **注册返回 disposer**——没有可逆性，HMR、preset 切换、会话隔离都会泄漏状态。
4. **拒绝方向**：未知必需事件拒绝重建、无沙箱后端拒绝执行、无审批应答者拒绝放行——**fail-closed 是默认值的设计**，不是错误处理的风格。

## 12.5 小结

最小 dsh = 插件运行时 + 事件溯源日志 + 流式词汇表 + 工具流水线 + 一个驱动循环 + 一条运行时不变量。其余一切——沙箱、审批、压缩、多 agent、Web UI——都是在这副骨架上按 seam 三角色模式长出来的肉。如果复刻过程中发现某个功能"必须改循环才能实现"，那多半是找错了 seam——回到[第 4 章](04-核心循环.md)的事件域表重新选挂点。
