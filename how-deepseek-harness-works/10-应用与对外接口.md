# 第 10 章：应用与对外接口——Web UI、RPC 与协议

> 本章导读：前面章节的一切都在一个 Node 进程内的插件树里。本章讲这棵树如何暴露给三类消费者：浏览器（Web UI）、外部进程（自有 JSON-RPC SDK、ACP 协议）、Python（SDK + 单 exe 运行时）。核心问题是"活对象如何跨进程"——Typert 是 dsh 的回答。建议先读[第 1 章](01-cordis与组装.md)（双面构建）与[第 4 章](04-核心循环.md)。

## 10.1 对外接口的三层

```text
浏览器 UI（apps/web + packages/client/*）
  ← BFF/RPC：packages/api（Typert gateway + remotes）、host/apiproxy
    ← Host 插件树（agent-loop 等）

外部进程（不经 BFF，stdio 驱动一个完整 harness 运行时）：
  packages/sdk（自有换行 JSON-RPC）  packages/acp（ACP 互操作协议）
  python/（封装 sdk 协议 + 单 exe 运行时）
```

CLI 本身只是启动器（[第 1 章](01-cordis与组装.md)），没有 TUI——`dsh web` 起 Web UI，`--profile headless` 跑一次性任务。

## 10.2 Web UI：从浏览器到 agent-loop

### Host 侧

`dsh web` 叠加 dsh-base + dsh-web-app 两层组合包。Host 插件树起 `dsh-host-webserver`（`ctx.webServer`，node:http；路由：精确表 → 最长前缀 → 单回退席位）。`dsh-client-modules` 扫描 loader 条目的 `dsh.client` 声明，组合 `window.__DSH_BOOT__` 启动图并注入 index.html；`/plugins/<id>/client.js?rev=` 供浏览器取模块 bundle；`frontend-static` 认领回退席位做 SPA。

### 浏览器壳

浏览器端复刻了 host 的架构纪律（见[第 2 章](02-仓库分层.md)的双面构建）：`packages/client/web/src/boot.tsx` 解析启动图 → 建 lazy CJS 模块表 → 预取标记 `immediately` 的模块 + 挂载 vendored Cordis Loader → 为每个插件创建 loader entry → 全部 fiber ACTIVE 后一次性渲染真 UI。**浏览器里也跑一棵 Cordis 插件树**——UI 模块是插件，跨模块协作走服务。

### 会话渲染：Conversation Node

会话事件经两条 WebSocket downlink（`/api/events.mux`、`/api/events.host`，事件按 allowlist 转发）到达浏览器，由 **ConversationNodeAssembler** 组装成渲染树：

- `ConversationNodeDefinition` 是"事件 → 节点"的状态机：`match/start/update/publication/buildLocationData/buildViewNode`；
- 渲染用 keyed renderer：`ctx.slots.register({name:'conversation.chat.node', key}, Component)`；
- 扩展点开放：注册新的 Definition + keyed renderer 就能加新的会话节点类型（workflow-run 折叠节点就是这样做的）。

### 安全边界

`/api` 前置 Host loopback 信任栅栏（DNS-rebinding 防御，明确非认证）——Web 服务默认绑 `127.0.0.1:3080`，且不信任"来自 localhost 的请求"这个说法本身，要在请求时做 origin/host 校验。

## 10.3 Typert：活对象如何跨进程

这是接口层最关键的设计。问题：Host 的 Cordis 服务方法签名含 `Agent` 等**活对象**，无法跨进程 wire；手写 RPC 会让 Host/Client 两侧漂移。

Typert 的回答是**构建期代码生成 + 显式 lookup**：

1. 服务方法标 `@Remote` 或 `@RemoteScope(key)` 注解——前者生成直接面向 Host Context 的调用面（`ctx.remote.<ns>`），后者经 `ctx.typert.contexts` 解析作用域 Context，生成面向 agent 作用域的调用面（`agentCtx.remote.<ns>`）；
2. 构建期用 `ts.Program` 严格分析这些方法，按 face 生成两份产物：Host 反射描述符（`typert.host.js`）+ Host-for-Client 贡献（`typert.remote-client.js`，含严格描述符与运行时 Zod codec）；
3. 复杂对象经 `TypertLookupMap` 声明换 wire identity——`agent` 参数在线上变成 `agentId`，Gateway 调用前经 lookup（`api/remotes/src/agent-lookup.ts`）解析回活对象：复用 live、冷会话自动恢复、并发去重，并拒绝由 subagent routing 拥有的 identity；
4. declaration map 让编辑器从 `ctx.remote.goals.create` 跳回 Host 源方法——**生成的代码保持可导航**。

调用路径：UI 插件调 `ctx.remote.<ns>.<method>` → `POST /api/<ns>/<method> {args}` → Typert interceptor 认领有描述符（或活跃 SRC marker）的 endpoint → `ctx.typertGateway.invoke` 校验 args → lookup 解析活对象 → 调业务服务；未认领的 endpoint 回退到既有 API Proxy（`packages/host/apiproxy`）。

源码启动（tsx）没有 ts.Program 时有 SRC 回退：decorator WeakMap + 参数名解析的弱描述符，仅解决 Host 分发；**Client 拒绝挂载非 strict 描述符**——降级只降在不影响正确性的地方。

## 10.4 自有 SDK 与 ACP：为什么并存

两者共用同一个形态：**stdio 子进程驱动一个完整的 cordis.yml 运行时**（jsonrpc-demo / acp-demo 组合包），但服务不同目的：

| | 自有 JSON-RPC SDK（packages/sdk） | ACP（packages/acp） |
|---|---|---|
| 定位 | harness 原生词汇的完整暴露 | 互操作协议，只承诺基线 |
| 暴露内容 | 完整 `SessionEvent` 信封流、`session.status`、`subagent.started/finished` 等 | 文本提示词、已提交回答、一次性权限 |
| 消费者 | Python/TS 自动化、`subagent-dsh-sdk` 后端 | 外部生态客户端（Zed 等 ACP 编辑器） |

并存的理由：自有 SDK 不必迁就外部协议的能力子集；ACP 让 dsh 能被不懂 dsh 的客户端驱动。ACP 还是 subagent 的一种 provider 传输（[第 9 章](09-编排能力.md)）——协议同时服务于"被驱动"与"驱动别人"。

## 10.5 Python SDK 与单 exe

`python/sdk` 封装 sdk 协议；`python/sdk-runtime` 是"纯依赖清单"——其依赖闭包就是单 exe 要打包的内容。构建产物为每平台一个 `dsh-jsonrpc-agent-pkg-<platform>-<arch>`（含 node 运行时与内置插件树，gitignore 里能看到这些产物名）。Python 用户 `pip install` 后拿到的是一个能自举的完整 harness——**Python 进程不需要系统里装 Node**。

## 10.6 设计取舍

**为什么 Web UI 要复刻 Cordis 到浏览器**：UI 模块同样需要可替换、可热更、effect 可逆；一套框架语义横跨两个运行时，比"host 插件 + 浏览器传统 React 应用"的双心智模型便宜。代价是构建系统要维护双面产出与 purity gate（client 面包间禁止直接 import 值）。

**为什么 Typert 生成具体函数而不是 Proxy**：Proxy 方案把类型错误推迟到运行时；生成的具体函数 + Zod codec 让参数错误在构建期（类型）与入口（codec 校验）各拦一次，且 declaration map 保持 IDE 导航。取舍是构建链里多了一个代码生成步骤，以及"活对象必须显式 lookup"的纪律。

**loopback 信任栅栏**：本地端口不等于安全——恶意网页可以对 `127.0.0.1` 发请求（DNS rebinding）。origin/host 校验把"信任 localhost"细化成"信任通过校验的客户端"。

## 10.7 关键实现入口

| 文件 | 职责 |
|---|---|
| `packages/host/webserver/src/index.ts` | ctx.webServer：路由与回退席位 |
| `packages/client/modules` | dsh.client 扫描、`__DSH_BOOT__`、bundle 路由 |
| `packages/client/web/src/boot.tsx` | 浏览器壳装配 |
| `packages/client/runtime/src/client/contract/conversation.ts` | ConversationNodeDefinition |
| `packages/client/runtime/src/client/sessions/conversation-assembler.ts` | 事件→节点组装器 |
| `packages/client/connection/` | /api 桥、信任栅栏、WS downlink |
| `packages/typert/{protocol,generator,registry,loader}` | 类型图生成/加载/运行时注册 |
| `packages/api/gateway`、`api/remotes` | RPC 网关与 BFF 装配（agent-lookup） |
| `packages/sdk/{protocol,server,client}` | 自有 JSON-RPC 协议栈 |
| `packages/acp/acp` | ACP 服务器 |
| `python/{sdk,sdk-runtime}` | Python SDK 与单 exe 依赖清单 |
| `packages/host/apiproxy` | 旧 API Proxy 回退与审批应答者 |

## 10.8 小结

接口层的系统模型：**Host 插件树是唯一事实；浏览器经双面构建复刻同一套插件语义；活对象跨进程靠 Typert 的构建期生成 + lookup；对外协议分"完整原生词汇（自有 SDK）"与"互操作基线（ACP）"两档；Python 拿到的是自举的完整运行时**。下一章收尾：如果要从零复刻这个架构，最小必要组件是什么。
